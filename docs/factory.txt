## Knowledge Base — Deep Dive

### What It Is

The knowledge base is the spinal cord of the software factory. It gives the agent (or any LLM working in this workspace) just-in-time, just-enough context about what exists, how it works, and why it was built that way — without overwhelming the context window.

It is not a dumping ground for all information. It is a **progressive disclosure system**: the agent starts with lightweight pointers, and drills deeper only when needed. This keeps the initial context footprint small (~2,500 tokens) while making the full depth of workspace knowledge accessible on demand.

### Core Problem It Solves

An LLM working on a large multi-project workspace needs three kinds of knowledge:

1. **What exists** — projects, files, structure
2. **How it works** — architecture, code, APIs, operations
3. **Why it was done that way** — design intent, vision, decisions, constraints

The first two are easy (code + READMEs + OpenWiki). The third is hard: it lives in the developer's head, in past conversations, in rejected alternatives. Without it, the agent makes changes that conflict with the intended direction, breaks undocumented constraints, or duplicates past work.

### Architecture — The Progressive Disclosure Chain

```
AGENTS.md (~250 tokens)
    │  "Code is truth. Start here for pointers."
    ▼
docs/factory-context.md (~3KB)
    │  "Here's every project, its status, its docs, and where to find the 'why'."
    ▼
┌──────────────────────────────────────────────────────┐
│                  Discovery Layer                      │
│                                                       │
│  openwiki/         Per-project code docs (what/how)   │
│  VISION docs       Stakeholder vision, end goals      │
│  PRDs / DESIGN     Product requirements, architecture  │
│  project READMEs   Operational guides                  │
│  .agents/skills/    Operational playbooks               │
└──────────────────────────────────────────────────────┘
    │
    ▼ (when design intent is needed)
┌──────────────────────────────────────────────────────┐
│                  Why Layer                            │
│                                                       │
│  docs/knowledge/   Curated design decisions & issues   │
│  session.jsonl     Full session traces for deep context │
└──────────────────────────────────────────────────────┘
```

Key principle: each layer is discovered on demand. The agent never loads everything — it follows pointers from the previous layer.

### Relationship to Other Factory Components

The knowledge base feeds every other component:
- **assembly_line** uses it so agents understand context before writing code
- **project_management** uses it to understand priorities and constraints
- **product/architecture** integrates with it to present intent to the user

Without the knowledge base, downstream components operate blind — they see code but not intent. With it, the entire factory has a shared understanding of what exists, how it works, and why.
