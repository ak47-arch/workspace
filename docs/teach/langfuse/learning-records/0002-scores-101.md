# Scores 101: configs, annotation queues, and manual scoring

The user understands the score data model: **score configs** (the definition: name + dataType BOOLEAN/NUMERIC/CATEGORICAL) are separate from **scores** (individual judgments attached to traces/observations). They saw the three creation paths — API/CLI config-first, annotation queues (human review), and LLM-as-judge (upcoming). They created real infrastructure live on the v4 instance: the `task-completion` BOOLEAN config (recreated after the v4 migration loss), the `response-quality` NUMERIC 1–5 config, and the `demo-queue-2026-08` annotation queue bound to task-completion.

Key v4 findings during the lesson: (1) `score-configs create` via `langfuse-cli` works, with v4 auto-generating True/False categories for BOOLEAN; (2) the CLI's `annotation-queues create` schema is a step behind — the `scoreConfigIds` option isn't exposed even though the API requires it, so queue creation used curl; (3) no scores exist yet — configs define shape, scores come with annotation/judges; (4) direct score creation is via **ingestion events** (`score-create`), not a REST create endpoint in v4.

This matters because annotation queues are the hands-on way to build labeled data, which is the prerequisite for calibrating LLM judges in Lesson 4. The exercise of scoring a real pi trace via `score-create` ingestion closes the loop: config → score → queryable data.
