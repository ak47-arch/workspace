Scores 101

Lesson 2 · 2026-08-09 · ~15 minutes

A score is a single judgment attached to something in Langfuse — a trace, an observation, a session. It answers the question: "was this good?". Scores are the currency of every evaluation. Everything you'll build later (manual review queues, LLM-as-a-judge, regression detection) reduces to scores: who scored what, how, and was it right?

Key insight A score is a number or label with a name. "response-quality = 4", "task-completion = True", "toxicity = 0.02". That's it. Evals are just ways of producing scores at scale.

The two building blocks

Langfuse separates what a score means from the score itself:

Block What it is When it exists
Score config The definition — name, type (BOOLEAN / NUMERIC / CATEGORICAL), optional range Before any scores exist. Like a column definition in a spreadsheet.
Score One actual judgment — config + a value attached to a trace/observation At evaluation time. Like a cell in that column.

The config's data type determines what a score can be:

Type Value Use for Example
BOOLEAN True/False (stored as 1/0) Yes/no judgments task-completion
NUMERIC Number, optional min/max Rating scales, metrics response-quality 1–5
CATEGORICAL Label from a fixed list Classification, error types failure-mode: tool_error / parsing / context

How scores get created

Three ways — from most manual to most automated. You'll use all three at different times.

1. Config first, score later (API / CLI)

The config is the source of truth. Create it once; scores reference it. On our v4 instance (2026-08-09): 

# via the langfuse CLI. Credentials come from .env.langfuse
source .env.langfuse
export LANGFUSE_HOST="$LANGFUSE_BASE_URL"

# Create a BOOLEAN config — v4 auto-creates True(1)/False(0) categories
npx -y langfuse-cli api score-configs create \
  --name "task-completion" \
  --dataType BOOLEAN \
  --description "Did the agent complete the requested task?"

# Create a NUMERIC config with a 1–5 range
npx -y langfuse-cli api score-configs create \
  --name "response-quality" \
  --dataType NUMERIC \
  --minValue 1 --maxValue 5

Both of these were run live while writing this lesson. The configs now exist in project pi-agent with IDs you can look up: 

npx -y langfuse-cli api score-configs get-public

2. Annotation queues (the human review workflow)

An annotation queue is a work queue for humans: "review these traces and score them". You point a queue at one or more score configs, add items (traces), and reviewers work through them. This is how you build labeled data by hand — the raw material for calibrating judges later.

Creating a queue (v4 API — the CLI's queue schema is a step behind):

AUTH="Authorization: Basic $(echo -n "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" | base64 -w0)"

curl -X POST http://localhost:3000/api/public/annotation-queues \
  -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "name": "demo-queue-2026-08",
    "description": "Lesson 2 demo",
    "scoreConfigIds": ["<task-completion-config-id>"]
  }'

Then add traces to it via POST /api/public/annotation-queues/<queue-id>/items with the trace IDs. Reviewers see each trace, score it against the config, and the scores land back in Langfuse.

3. Automatic scoring (LLM-as-judge — Lesson 4)

A judge model reads a trace's input/output and emits a score — no human in the loop. Same configs, same score shape, produced at scale. This is where calibrated judges matter; that's Lesson 4's territory.

Insight for your factory Scores attach to traces, but in v4 eval rules target observations (the migration doc: legacy trace-level rules must move to observation-level). When you score, think about which observation carries the output being judged.

Exercise: score a real trace manually (via API)

Pick a trace from your own real data, then attach a manual numeric score to it:

source .env.langfuse
AUTH="Authorization: Basic $(echo -n "$LANGFUSE_PUBLIC_KEY:$LANGFUSE_SECRET_KEY" | base64 -w0)"
TRACE_ID="<id from the Traces list>"

# Ingest a score event (v4 ingestion accepts score-create events even in dual mode)
curl -X POST http://localhost:3000/api/public/ingestion \
  -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"batch":[{
    "id":"manual-score-1",
    "timestamp":"'"$(date -u +%Y-%m-%dT%H:%M:%S.000Z)"'",
    "type":"score-create",
    "body":{
      "traceId":"'"$TRACE_ID"'",
      "name":"response-quality",
      "value":4,
      "comment":"Solid answer, one tool retry"
    }
  }]}'

# Verify it landed
npx -y langfuse-cli api scores-v3s list

That score — a real judgment on a real trace — is now queryable, filterable, and ready to compare against judge scores later.
